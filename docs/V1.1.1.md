# SENTINEL Enterprise V1.1.1 corrective release

The Windows-installed V1.1 Demo executive PDF exposed three content defects: the
executive first priority differed from the grouped remediation plan, one modeled
reduction displayed as both 70.2 and 70.3, and the VPN-to-domain-controller path
borrowed segmentation evidence whose affected assets did not include that tier.

## Corrections

- Executive and technical reports select the same highest-priority grouped action
  as the remediation engine, including deterministic ID tie ordering and top-ten
  selection. The highest-risk individual finding is explicitly distinguished.
- Business reasons use the published reduction and confidence values with
  invariant formatting. Stored risk arithmetic and scoring coefficients remain
  unchanged.
- Fresh Demo segmentation evidence explicitly covers application and VPN gateway
  tiers and both domain controllers. Identifiers and root-cause keys remain stable.
- Asset-to-asset path prerequisites must reference at least one endpoint asset,
  including graph aliases. Unsupported scoped prerequisites are excluded from
  analysis without modifying the stored evidence. Identity/service relationships
  retain their recorded relationship model.

## Existing installations and data

Install the V1.1.1 Setup over V1.0 or V1.1. Operator SQLite evidence, history,
settings, DPAPI data, service settings/audit and desktop planning/review metadata
are preserved. Existing Demo snapshots are not silently regenerated or rewritten.
An older Demo snapshot with the unrelated gateway prerequisite consequently shows
four supported paths; a fresh corrected Demo has five. This is a change in
supported inference, not a claim that an operator performed remediation.

The corrected fresh fixture can have different modeled totals because its
segmentation finding now explicitly covers five assets instead of three. Stored
historical scores remain historical and are not rewritten. Live collection,
authorization boundaries and database schema are unchanged.

## Acceptance and release

The Windows workflow builds with warnings as errors and runs product, engine,
publication and actual installed-assembly Desktop checks. New behavioral checks
cover grouped priorities, tied top-ten selection, numeric/culture consistency,
accepted risk, unknown coverage, corrected gateway evidence, legacy snapshot
preservation and graph alias scopes. Installed reporting tests export real PDF
and JSON and check narrative/plan/rounding agreement; settings are saved and
verified after restarting the real Desktop window.

Upgrade gates use checksum-pinned genuine public V1.0 and V1.1 installers rather
than approximations. V1.1 planning/review metadata is seeded and loaded through
the installed Desktop store. Database, secrets, service data and workflow files
must remain intact after upgrade and uninstall. The complete 360-render matrix
is retained. Historical tags/assets remain immutable.

The corrective development gate [37637697000](https://github.com/ever2vip/SENTINEL/actions/runs/37637697000), source `2bd83211c6cc5441f1336523a961dceb50eee208`, passed a zero-warning/error Release build, 100 product checks, 17 engine checks, 14 publication safeguards, 61 installed Desktop checks and 28 installer/service/upgrade/uninstall checks. No checks failed; one machine-dependent endpoint check was explicitly skipped. The installed Desktop produced 369 PNGs including the full 360 matrix; all 20 routes were reviewed in Dark and Light. Its exported nine-page PDF and JSON agreed on the first remediation priority, all ten displayed reduction/confidence values, corrected gateway evidence and full report content. The release branch repeats all gates before creating the immutable `v1.1.1` tag and publishing verified assets.
Physical Windows 10/11 and native DPI transitions remain manual acceptance.
The installer is unsigned and the release is a Windows testing prerelease.
